# 评测报告（检索 / 引用 / 抗幻觉）

> 目的：让"混合检索有效""引用可溯源"这类结论有可复现的数字，而不是只靠演示观感。
> 环境：本机 2026-10-29；PostgreSQL 18 + pgvector；embedding bge-m3（1024 维）；
> chat 模型 siliconflow `deepseek-ai/DeepSeek-V3`；api 127.0.0.1:3210。
> 复现：仓库 `docs/competition/eval/`（`retrieval-eval.mjs` + config.example.json）。

## 1. 检索评测（7 条查询）

方法：调用 `POST /knowledge-bases/{id}/search`（即混合检索：向量 + 中文 bigram FTS + RRF），
对每条查询记录"期望命中的文档 + 页码（any-of，容忍跨页/OCR 差异）"在 top-5 中的排名。

| # | 查询 | 知识库 | 命中排名 | top-3（页码） |
|---|---|---|---:|---|
| q1 | 训练用了多少块 GPU？ | PDF 学术解析验证 | 1 | p8 / p8 / p2 |
| q2 | WMT 2014 英德 BLEU 分数 | PDF 学术解析验证 | 1 | p8 / p7 / p1 |
| q3 | self-attention 的计算复杂度为什么比 RNN 低？ | PDF 学术解析验证 | 2 | p2 / p6 / p6 |
| q4 | Table 2 的 BLEU 结果是多少？ | PDF 学术解析验证 | 3 | p7 / p7 / p8 |
| q5 | overfitting | UDL 541 页 | 1 | p139 / p142 / p36 |
| q6 | convolutional layer | UDL 541 页 | 1 | p195 / p180 / p179 |
| q7 | 读书笔记 | 中文笔记库 | 1 | md / md / md |

**汇总**：hit@1 = **71.4%**（5/7），hit@3 = **100%**（7/7），MRR = **0.833**。

> 说明：q1 的期望页是 7/8（正文"8 块 GPU"在 p7，Table 2 说明在 p8），命中 p8 判对；
> q3 期望页 5/6（Why Self-Attention 一节跨页），命中 p6 判对；
> q4 的 Table 2 标题行在 p7、表格主体在 p8，top-3 内命中。

## 2. 引用页码与引用落地检查（3 条问答）

方法：走真实问答链路（SSE），读持久化后的 assistant 消息，检查 citations 的 page 与 grounding。

| # | 问题 | citations 页码 | 期望页 | 页码命中 | grounding |
|---|---|---|---|---:|---|
| c1 | Attention 论文训练用了多少块 GPU？ | 2, 2, 3, 2, 7 | 7/8 | ✅ | valid（1/1 句） |
| c2 | WMT 2014 英德 BLEU 分数 | 8, 7, 1, 8, 10 | 8 | ✅ | valid（1/1 句） |
| c3 | 这篇论文的 self-attention 是如何工作的？ | 6, 6, 2, 5 | 2/3/4/5 | ✅ | 部分未溯源（2/3 句） |

**汇总**：引用页码命中 **3/3**；grounding 通过 **2/3**（c3 有一句没有标注引用，
前端如实显示"部分未溯源"——这正是机制要暴露的情况，而不是掩盖）。

## 3. 抗幻觉拒答（定性）

在无关主题（如"量子纠缠与贝尔不等式"）上提问：检索结果为空 → 系统不调用模型 →
返回固定拒答文案，grounding 事件 `valid=false`，**0 幻觉**。
（对应技术文档 §4.5.1 的第三道闸门。）

## 4. 局限

1. 评测集只有 7 条检索 + 3 条问答：证明链路可量化，不足以代表整体分布；
2. 页码 any-of 容忍了跨页差异，因此不能区分"命中相邻页"与"命中精确页"；
3. grounding 是规则检查（编号合法性/句子覆盖），不判断语义一致性；
4. 未做多模型横向对比（只比较了 DeepSeek-V3 与 Qwen2.5-7B 的引用合规观感）。

## 6. 近重复抑制 A/B（多版本论文去重）

同一篇 Attention 论文在知识库里有两个版本（PDF 原文 + 扫描件），两者正文
高度重合。评测脚本统计 top-3 内 Jaccard ≥ 0.85 的近重复对：

| 配置 | q1 top-3 | 近重复对 | hit@1 |
|---|---|---:|---:|
| `CONGORAG_RETRIEVAL_DEDUP=off` | v1_img p8 / v1 p8 / v1 p2 | 1 | 71.4% |
| 默认（开启） | v1_img p8 / v1 p2 / v1_img p7 | 0 | 71.4% |

去重实现：小写 + 只保留字母数字归一化，字符 5-gram Jaccard，阈值 0.85，
按 RRF 排名贪心保留。**7 条评测集里只有 1 条触发，但机制与阈值可复现**；
更大评测集下应继续观察"去重是否误伤真正互补的相邻段落"。

## 7. 性能与用量数据（本机实测）

| 指标 | 数据 |
|---|---|
| 混合检索延迟（10,573 分块，24 次，topK=5） | 平均 **154 ms**，P95 **178 ms**，min 141 / max 229 ms |
| 库规模 | 17 份 ready 文档 / 572 页 / 10,573 分块 / 表 66 MB |
| 解析耗时 | 15 页 3.1 s；541 页冷解析约 122 s（缓存命中 <1 s） |
| Token 用量（开发期累计） | embedding 1.67M / 464 次；chat prompt 153K / completion 2K / 92 次 |

> 说明：延迟是"检索接口"端到端（embedding 调用 + 向量 + FTS + RRF + 去重），
> 不含模型回答时间；开发期 token 用量包含反复重索引与评测调用，不代表单次
> 演示成本。

## 5. 复现步骤

```bash
# 1. 启动服务、配置模型、上传演示文档（见仓库 docs/competition/README.md）
# 2. 复制并填写评测配置（把 uuid 换成你自己的库/文档）
cp docs/competition/eval/config.example.json /tmp/eval-config.json
# 3. 运行
node docs/competition/eval/retrieval-eval.mjs /tmp/eval-config.json
# 输出：eval-results.json（检索 + 引用两组指标）
```
