# 答辩问答（预演）

> 决赛答辩占决赛总分 30%：代码架构讲解 + Prompt 审计记录 + 现场 Demo。
> 这里按评委最可能问的 14 个问题准备，每题给一句话结论 + 证据位置。

## A. 架构与选型

**Q1：为什么是 Go + 模块化单体，而不是 Python 微服务？**
本地优先的科研工具，单用户、要交付一个可一键启动的二进制。Go 的 `go:embed`
把前端打进单文件，两个进程（api/worker）共享一份 pgx 连接池，部署成本最低。
模块边界用 Go 包表达而不是网络边界：业务包不 import gin、不知道 HTTP 状态码，
由 `internal/arch_test.go` 用 AST 强制（ADR-001）。
证据：`docs/adr/001-modular-monolith.md`、`internal/arch_test.go`、`Dockerfile`。

**Q2：Agent 用什么编排？为什么不用 LangGraph/多 Agent？**
Eino（CloudWeGo）做工具循环，单 Agent + 工具注册表。当前场景是检索→工具→
生成的线性循环，多 Agent 路由只会多一层不可审计状态。所有 tool_call /
tool_result 逐步落库，运行可取消、可从断点恢复。
证据：`internal/agent/`、`docs/adr/006-checkpoint-layering.md`、`docs/adr/007-recovery-semantics.md`。

**Q3：引用了这么多 ADR，最有价值的一条是哪条？**
为什么客户端不用 EventSource（ADR-005）：POST + 自定义头 + 自己控重连，三者它
都做不到；我们因此自己写分帧与续传，也为后来加 SSE 心跳留下空间。
证据：`docs/adr/005-sse-over-fetch.md`、`web/src/lib/streamChat.ts`、`docs/sse-protocol.md`。

## B. 抗幻觉与检索

**Q4：怎么保证回答有依据？**
三道闸：①检索层混合召回（中文 bigram 词法 + pgvector 向量 + RRF k=60 融合）；
②生成层系统提示要求逐句 [n]，citation 随 SSE 先于正文下发；③结束层
`grounding.Verify` 做句子级落地检查（覆盖率、编造编号检测），无证据时固定
拒答、不调模型。
证据：`internal/retrieval/`、`internal/grounding/grounding.go`、`internal/conversation/usecase.go`。

**Q5：混检索的分数怎么算？为什么 RRF 而不是加权求和？**
两路分数尺度不同（cosine 与 ts_rank_cd），直接加权要调归一化参数；RRF 只用
名次（1/(60+rank)），对尺度不敏感、对新增一路也稳定。检索调试接口同时返回
vectorScore / lexicalScore / score，现场可看每一路贡献。
证据：`internal/retrieval/usecase.go`、`POST /knowledge-bases/{id}/search`。

**Q6：halfvec 是什么？为什么不是 float32 向量？**
pgvector 的 halfvec 把每维从 4 字节降到 2 字节，HNSW 索引内存减半、构建更快，
top-k 召回实测损失在可接受范围；代价与限制写在 ADR 里。
证据：`docs/adr/004-halfvec-embeddings.md`、`migrations/`。

**Q7：去重为什么不用 embedding？**
去重跑在每条检索请求的主路径上，多一次模型调用就多几百毫秒；同文不同版字符
5-gram 重合度极高，足够。v6.2.0 把集合表示换成排序去重的 64 位哈希：同机对照
212,455→161,184 ns（−24.1%）、3,354→22 allocs/op。embedding 相似度留给
rerank/MMR，属于 Roadmap。
证据：`internal/retrieval/dedupe.go`、`docs/performance.md`。

## C. 工程与可靠性

**Q8：流式回答断线了怎么办？**
带 `after_event_id` 请求 `/conversations/{id}/events` 补发之后的事件；同一条消息
带同一个 `Idempotency-Key` 重发不会重新生成，按原 event_id 补发。补完即结束，
不持有连接。v6.4.0 起空闲 15s 补 `: keep-alive` 注释帧，防反代掐断。
证据：`docs/adr/008-idempotency-replay-window.md`、`docs/sse-protocol.md`、`apps/api/internal/api/sse.go`。

**Q9：进程被杀之后，Agent 运行会怎样？**
run 停在 running，启动扫描标 interrupted；恢复入口从库里的 step 编号继续，
不重放副作用等级不允许重放的步骤（三道拒绝理由各有错误类型）。崩溃探针
（SIGKILL）做过两次真实观测并留档。
证据：`docs/testing.md`、`scripts/crash-probe.mjs`、`apps/api/internal/api/handler_agent.go`。

**Q10：怎么防提示词被悄悄改掉？**
提示词进注册表（v6.3.0）：版本、完整文本、SHA-256、变更原因、采样参数、代码位置；
启动校验；界面只读审计页；采样参数真正传给模型（之前被适配器丢弃，是本轮修的）。
证据：`internal/prompt/`、`docs/prompt-audit.md`、`docs/adr/010-prompt-registry.md`、`GET /api/v1/prompts`。

**Q11：安全做了什么？**
默认只绑回环 + Origin/Host 校验；安全响应头（CSP/nosniff/DENY 等）；双档令牌桶
限流（超限 429 + Retry-After）；上传扩展名白名单 + 内容嗅探 + 文件名净化；
API Key AES-GCM 加密落库；SSE 写锁防帧交错。
证据：`SECURITY.md`、`internal/platform/security.go`、`internal/platform/ratelimit.go`、`internal/knowledge/upload_validation.go`。

**Q12：怎么证明不是只做了界面？**
六轮迭代的 commit/tag 可查：v6.2.0→v6.7.0；Go 800+ 用例、前端 200+ 用例、
14 条 benchmark、E2E 冒烟、压测报告、bench 门禁；每个结论都有可复跑命令。
证据：`CHANGELOG.md`、`docs/iterations.md`、`docs/quality-baseline.md`。

## D. 场景与价值

**Q13：和 RAGFlow / Dify 有什么区别？**
它们面向搭应用，我们面向读论文这一条链路：页级/坐标级引用锚点、双语联动阅读、
引用图谱 + PageRank 基石论文、Future Work 去重、版本差异、写作 Copilot 与图表
代码生成都在同一条检索+引用主线上，而不是插件拼装。
证据：`docs/modules.md`、`landing/`、`README.md`。

**Q14：局限与下一步？**
单用户、无鉴权（部署边界是本地/反代后）；中文分词用 bigram 近似；大 topK 去重
仍是 O(n·k)；多用户/按账号限流、MinHash/LSH、rerank 属于 Roadmap。
证据：`README.md` 已知限制、`docs/performance.md` 已知热点、ADR 的"如果将来要重新考虑"小节。

## 现场演示的故障切换

- 模型服务挂/额度不足：切到已缓存的演示数据与录屏；`upstream_llm_error` 的
  错误边界会把原因显示在页面上，不会白屏。
- 网络/反代不可用：本地 `make dev` + `deployments/docker` 起 PostgreSQL，演示
  离线闭环（检索、引用、图谱、Prompt 审计都不依赖外网）。
- 最坏情况：直接讲架构图 + 展示仓库/测试报告/CHANGELOG，不依赖现场环境。
